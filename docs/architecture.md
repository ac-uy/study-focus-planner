# Architecture

## Overview

```
Browser (web-next app, localStorage copy)
   |  HTTPS
CloudFront  --->  S3 (private bucket, origin access control)      static files: /, /next/
   |
   |  HTTPS + Cognito JWT
API Gateway (HTTP API, JWT authorizer)  --->  Lambda (Node 22)  --->  DynamoDB
                                                  |--> Bedrock (Nova models, eu inference profiles)
                                                  |--> YouTube Data API (key in SSM Parameter Store)
Cognito user pool (hosted sign-in page, code flow with PKCE)
```

Region and account come from `infra/config.local.json` (not in the repository). Stack name `StudyPlannerStack`. Deployments use an AWS CLI profile named `planner`.

## Hosting
- One private S3 bucket behind CloudFront. A CloudFront Function maps `/next/` to `/next/index.html`.
- `web/` is deployed to the root, `web-next/dist` to the `next/` prefix. Each has its own `config.json` (client id, Cognito domain, API URL, redirect URI) generated by CDK.
- `app.js`, `app.css`, `index.html` and `config.json` are served with `no-cache`.

## Authentication
- Cognito user pool, no self sign-up. Users are created by an administrator (today also by CDK resources, see change 0001).
- App client with authorization code and PKCE. Callback URLs: site root and `/next/`.
- ID token valid 1 hour, refresh token 30 days. The browser keeps them in localStorage (`sp2-auth`).
- API Gateway rejects calls without a valid token. The Lambda reads `sub` and `email` from the verified claims. The browser never sends a user id.

## API (all routes need a token)

| Route | Purpose |
| --- | --- |
| `GET/PUT /api/data` | v1 whole-document storage (used by `web/` and for the one-time import) |
| `GET /api/v2`, `PUT /api/v2/{section}` | v2 storage by section: `core`, `notes`, `cards`, `sessions` |
| `POST /api/ai/steps` | goal step suggestions |
| `POST /api/ai/chat` | tutor, optionally with up to 3 photos per message |
| `POST /api/ai/review` | photo review of handwritten work |
| `POST /api/ai/exam` | mini exam from study material |
| `POST /api/ai/cards` | flashcards from notes |
| `POST /api/music/search` | filtered YouTube search |
| `POST /api/music/check` | check a pasted YouTube link |
| `GET /api/me` | role and links of the signed-in account (children for a parent, parents for a child) |
| `GET/POST /api/parent/children` | parent only: list linked children, create a child account |
| `GET /api/parent/children/{childSub}/data` | parent only: read-only, filtered copy of one linked child's data |

Throttle: 5 requests per second, burst 10. Lambda: 512 MB, 30 s.

## Data (DynamoDB, one table, pay per request, point-in-time recovery on, kept on stack deletion)

| Partition key | Sort key | Content |
| --- | --- | --- |
| `USER#<sub>` | `DATA` | v1 document |
| `USER#<sub>` | `V2#core`, `V2#notes`, `V2#cards`, `V2#sessions` | `body` (JSON string), `updatedAt` (ms) |
| `USER#<sub>` | `PROFILE` | role (`parent` or `child`), name, email, createdAt, createdBy, lastSeen |
| `USER#<parent>` / `USER#<child>` | `CHILD#<child>` / `PARENT#<parent>` | the two sides of a parent-child link |
| `USER#<sub>` | `AI#<date>`, `CHAT#<date>`, `REVIEW#<date>`, `EXAM#<date>`, `CARDS#<date>` | daily usage counter `calls`, expires after 3 days |

Each section is capped at 360 KB on the server (300 KB in the app). The newest `updatedAt` wins per section.

## What is stored on the device (localStorage)
`study-planner-v2` (all data and timestamps), `sp2-auth` (tokens), `sp2-bgphoto` (her background photo, never uploaded), `sp2-lastquote`, `sp2-music-auto`, `sp2-yt-host`. The v1 page uses `study-planner` and `study-planner-auth`.

## AI models (Amazon Bedrock, EU inference profiles)
- `eu.amazon.nova-lite-v1:0`: step suggestions, tutor text, flashcards, music text filter.
- `eu.amazon.nova-2-lite-v1:0`: photo review, mini exams, tutor messages that include photos.
- Photos are sent for one call and never stored.

## Limits and costs
- Daily per user: steps 30, tutor 100, reviews 30, exams 30, flashcards 30. Music search has no cap of its own. YouTube allows about 10,000 quota units a day for the key (a search costs 100, the details check 1).
- Account budget of USD 5 a month with email alerts at 50%, 80%, 100% of actual spend and at a forecast of 100%, plus a daily anomaly alert from USD 2. Alerts go to the owner's email. Nothing stops automatically.
- Other budgets in the account may belong to other projects. This stack does not manage them.

## Secrets
YouTube Data API key: SSM parameter `/study-planner/youtube-api-key` (SecureString), read by the Lambda only.

## Build and deploy
`npm test` builds `web-next/dist` and runs the tests. `npm run deploy` in `infra/` builds, then `cdk deploy`. Tests do not call AWS.
